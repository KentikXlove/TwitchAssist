# Logger – простой и гибкий логгер для Python

![version](https://img.shields.io/badge/version-1.0.0-blue) ![license](https://img.shields.io/badge/license-MIT-green) ![status](https://img.shields.io/badge/status-stable-brightgreen) ![python](https://img.shields.io/badge/python-3.6%2B-blue)

**Logger** — это легковесный пакет для логирования на Python, который автоматически сохраняет сообщения в файлы с меткой времени в имени. Он не требует внешних конфигурационных файлов — все настраивается через параметры конструктора. Поддерживает стандартные уровни (DEBUG, INFO, WARNING, ERROR, CRITICAL), а также кастомный уровень `SYSTEMERROR` для системных ошибок.

## ✨ Особенности

- Автоматическое создание папки для логов (по умолчанию `logs/`) 
- Имя файла содержит дату и время запуска (например, `log_2026-08-02_15-30-45.log`) 
- Возможность отключить временную метку в имени файла (тогда файл перезаписывается при каждом запуске) 
- Гибкая настройка формата сообщений и формата даты 
- Поддержка дублирования вывода в консоль (stdout/stderr) 
- Кастомный уровень `SYSTEMERROR` (числовой уровень 45) для выделения системных сбоев 
- Метод `exception()` для логирования исключений с полным стеком вызовов 
- Полная совместимость со стандартным модулем `logging`

## 🚀 Быстрый старт

```python
from packages.logger import Logger

# Создаём логгер с настройками по умолчанию
log = Logger()

# Логируем сообщения
log.info("Приложение запущено")
log.warning("Низкий заряд батареи")
log.error("Ошибка подключения к базе данных")
log.systemerror("Системный сбой: нехватка памяти")
log.critical("Критическая ошибка, требуется перезагрузка")
```

После выполнения в папке `logs/` появится файл с именем вида `log_2026-08-02_15-30-45.log`, содержащий все записи.

## ⚙️ Параметры конструктора

```python
Logger(name=None, log_dir="logs", filename_prefix="log", use_timestamp=True,
       level=logging.DEBUG, console_output=False, fmt=None, datefmt=None)
```

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| `name` | `str` | `None` | Имя логгера (отображается в записях). Если `None` — используется имя модуля.  |
| `log_dir` | `str` | `"logs"` | Директория для лог-файлов (создаётся автоматически).  |
| `filename_prefix` | `str` | `"log"` | Префикс имени файла (к нему добавляется дата/время, если `use_timestamp=True`).  |
| `use_timestamp` | `bool` | `True` | Если `True` — в имя файла добавляется дата и время запуска. Если `False` — используется только префикс (файл перезаписывается).  |
| `level` | `str` или `int` | `logging.DEBUG` | Минимальный уровень логирования (например, `"INFO"`, `logging.WARNING`).  |
| `console_output` | `bool` | `False` | Если `True` — сообщения дублируются в консоль (stderr).  |
| `fmt` | `str` | `None` | Строка формата сообщения. По умолчанию: `"%(asctime)s - %(name)s - %(levelname)s - %(message)s"`.  |
| `datefmt` | `str` | `None` | Формат даты/времени. По умолчанию: `"%Y-%m-%d %H:%M:%S"`.  |

## 📚 Методы логгера

Все методы принимают сообщение и произвольные аргументы (как в стандартном `logging`). 

### Основные методы

| Метод | Описание |
|-------|----------|
| `debug(msg, *args, **kwargs)` | Логирование отладочной информации  |
| `info(msg, *args, **kwargs)` | Логирование информационных сообщений  |
| `warning(msg, *args, **kwargs)` | Логирование предупреждений  |
| `warn(msg, *args, **kwargs)` | Синоним `warning`  |
| `error(msg, *args, **kwargs)` | Логирование ошибок  |
| `critical(msg, *args, **kwargs)` | Логирование критических ошибок  |
| `fatal(msg, *args, **kwargs)` | Синоним `critical`  |
| `systemerror(msg, *args, **kwargs)` | Кастомный уровень 45 для системных ошибок  |
| `exception(msg, *args, **kwargs)` | Уровень ERROR, автоматически добавляет информацию об исключении (traceback)  |
| `log(level, msg, *args, **kwargs)` | Логирование с произвольным уровнем (уровень можно передать строкой или числом)  |

### Утилитные методы

| Метод | Описание |
|-------|----------|
| `set_level(level)` | Изменяет уровень логирования после создания логгера  |
| `get_filepath()` | Возвращает полный путь к текущему лог-файлу  |
| `get_logger()` | Возвращает оригинальный объект `logging.Logger`, чтобы добавить свои обработчики или фильтры  |

## 💡 Примеры

### 1. Логгер с консольным выводом и кратким форматом

```python
from packages.logger import Logger

log = Logger(
    console_output=True,
    fmt="%(asctime)s [%(levelname)s] %(message)s",
    datefmt="%H:%M:%S"
)

log.debug("Это отладочное сообщение")
log.info("Информационное сообщение")
```



### 2. Логирование исключений

```python
from packages.logger import Logger

log = Logger()

try:
    1 / 0
except ZeroDivisionError:
    log.exception("Произошло деление на ноль")
```

В лог-файл будет записано сообщение с полным стеком вызовов. 

### 3. Изменение уровня во время работы

```python
from packages.logger import Logger

log = Logger(level="DEBUG")

log.set_level("WARNING")
log.info("Это сообщение не попадёт в лог (уровень выше INFO)")
log.warning("А это предупреждение попадёт")
```



### 4. Отключение временной метки в имени файла

```python
from packages.logger import Logger

log = Logger(use_timestamp=False, filename_prefix="app")
# Файл будет всегда logs/app.log (перезаписывается при каждом запуске)
```



### 5. Использование кастомного уровня SYSTEMERROR

```python
from packages.logger import Logger

log = Logger()
log.systemerror("Сбой в системном модуле: потеря связи с датчиком")
```

Такой уровень удобно использовать для мониторинга и алертинга, отделяя системные проблемы от обычных ошибок. 

---

## 🛠 Кастомный уровень SYSTEMERROR

Уровень `SYSTEMERROR` имеет числовое значение **45** (между `ERROR` (40) и `CRITICAL` (50)). Он зарегистрирован в модуле `logging` как `"SYSTEMERROR"`. Вы можете использовать его так же, как и стандартные уровни. 

Если вы хотите использовать его в стандартных настройках, передавайте строку `"SYSTEMERROR"` в методы `log()` или `set_level()`.
